## 수정

- `.gitignore`를 복구해 실행 환경·JWT·업로드·로그·DB·자격증명 파일·백업을 제외합니다. 기본 `.dockerignore`도 복구합니다. 이미 추적하던 백업 ZIP 두 개와 `.DS_Store`를 현재 소스 트리에서 제거합니다. 과거 커밋을 삭제하거나 기존 사용자 데이터를 변경하지 않습니다.
- `scripts/check-public-boundaries.py`는 배포 패키저의 제외 정책을 재사용해 강제로 추적된 비공개 경로도 CI에서 거부합니다. 경로 검사이며 파일 내용에 들어간 비밀값을 탐지하는 스캐너는 아닙니다.
- GitHub Actions는 읽기 권한만 사용하며 실행 자격증명을 체크아웃에 남기지 않습니다. Python/Node 테스트, 별도 PostgreSQL 통합 테스트와 정적 UI·Go 빌드를 실행합니다. 실제 LLM·Splunk·AWS 자격증명이 필요하지 않습니다.
- 최초 관리자 비밀번호 저장은 PostgreSQL의 조건부 원자적 쓰기로 처리합니다. 동시 초기화 요청 중 하나만 성공하며 나머지는 기존 비밀번호를 덮어쓰지 못합니다. 초기화 완료 후 요청은 bcrypt 전에 거부합니다.
- 브리지 토큰을 보내는 HTTP 연결은 루프백 또는 기본 Docker 서비스 이름 `range-bridge`로 제한합니다. 원격 호스트는 인증서가 검증되는 HTTPS가 필요합니다. 내부 Docker 네트워크의 관리자는 여전히 신뢰 경계에 포함됩니다.

## 재검증 방법

```sh
python3 scripts/check-public-boundaries.py
python3 -m unittest discover -s scripts/tests -v
sh scripts/local-test.sh
docker build --target go-build -f Dockerfile.local .
```

`local-test.sh`는 공개 포트·영구 볼륨이 없는 별도 `artex_test` DB를 사용합니다. 전역 관리자 설정을 변경하는 HTTP 회귀 테스트는 `ARTEX_TEST_DISPOSABLE_DB=1`과 실제 DB 이름 `artex_test`를 확인한 뒤 실행합니다. 실서비스나 일반 개발 DB를 이 테스트에 연결하지 마세요.

Splunk 대용량 응답 테스트의 모의 서버는 응답 전에 검색 POST 폼을 읽도록 보완했습니다. 커넥터의 응답 크기·완전성 제한은 유지합니다.
